# Local machine handover — 2026-08-04

For whoever runs the next local test. Written because a handover that says
"run the experiments" and not *which interpreter, from which directory, with
which command* has cost time here before.

## The one thing that matters: take the GPU lock

One card, one job. Do **not** launch a Python experiment directly — two jobs on
this GPU is how 42 minutes of training died, and every "noise floor" measured
in this repo has turned out to be a second job on the same card.

```bash
cd /home/fakemitch/pinokio/api/alexandria-audiobook2.git
export GPU_LOCK=$HOME/.alexandria_gpu.lock
export GPU_QLOG=$PWD/ab_test_runtime/logs/gpu_jobq.log

./gpu_job.sh <job-name> <command...>
```

It blocks until the card is free, refuses to run if the lock cannot be taken
(exit 4), records `QUEUED / IDENT / START / OK|FAILED` in `$GPU_QLOG`, and
propagates the wrapped command's exit code. `IDENT` records the commit,
dirty-tree hash, SHA-256 of `gpu_job.sh` itself, host, GPU and command **before**
the job starts, so a run can be traced to the code that produced it.

Check what holds the card:

```bash
tail -5 ab_test_runtime/logs/gpu_jobq.log
rocm-smi --showuse | grep 'GPU use'
```

## Running an experiment

Pattern, with a real example:

```bash
cd /home/fakemitch/pinokio/api/alexandria-audiobook2.git
export GPU_LOCK=$HOME/.alexandria_gpu.lock
export GPU_QLOG=$PWD/ab_test_runtime/logs/gpu_jobq.log
cd app

../gpu_job.sh nonprose_mechanism \
    timeout 5400 ../app/env/bin/python -u experiments/nonprose_mechanism.py \
    > ../ab_test_runtime/logs/nonprose_mechanism.log 2>&1
```

`timeout` is not decoration: a TTS run that wedges will otherwise hold the lock
forever and silently block everything queued behind it.

Every experiment takes `--seed` (default 1234) and writes to
`ab_test_runtime/experiments/<name>.json`. **Generation is deterministic when
seeded** — verified twice today, most recently by an accidental re-run of
`nonprose_mechanism` that reproduced all 8 segments × 5 ablations, the summary
and the verdict identically.

| script | what it measures | ~runtime |
| --- | --- | --- |
| `experiments/nonprose_mechanism.py` | ablates digits/caps/punct/syntax on failing non-prose | 20 min |
| `experiments/instruct_listening.py` | renders the 3 instruction arms as audio to compare by ear | 2 min |

## Traps that have actually bitten, in this repo, today

**Do not edit a running shell script.** Bash reads a script incrementally, so
overwriting one mid-execution corrupts it. Editing `gpu_job.sh` while it was
running **restarted a 20-minute job**, and editing `tts.py` while a queue ran
against it left generation broken for two minutes. Python is safe once the
module is imported; bash is not. Stage to a new filename and swap when idle.

**Do not chain jobs by waiting on a PID.** A tmux driver stayed alive after its
work finished and two queues waited on it while the card sat idle for twenty
minutes. Use `gpu_job.sh` — its `flock` is the only concurrency mechanism that
should exist here.

**`$(...)` resets `$?`.** `echo "$(date) rc=$?"` reports *date's* exit status,
not the command's. That made a failing run report `rc=0` today. Capture `rc` on
its own line first.

**Two artifacts can look identical.** `instruct_value.json` (unseeded) and
`instruct_value_seeded.json` (seeded) have the same shape, arms and row count,
and the older ones record no seed. I quoted the wrong one and published it. New
artifacts carry a `provenance` block (`experiments/provenance.py`) with seed,
script, git state and full arguments; the older ones do not. **Check
`provenance.seed` before quoting a number**, and if it is absent, do not assume.

**The results index does not cover everything.** `collect_results.py` indexes
per-arm attribution results only. 66 of 228 artifacts — including every TTS and
audio experiment — are listed under "Not indexed" in `RESULTS_INDEX.md` with a
reason. Absence from the index is not absence of a result.
