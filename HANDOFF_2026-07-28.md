## The per-style routing design — NOT YET TESTED

Four interventions split the same way and the split is large:

| | grimgar03 | mushoku16 |
|---|---|---|
| w4 context | +10.5 | −5.0 |
| batch size peak | 50 | 25 |
| tag-priority | +6.5 | −5.8 |
| narrator prior (own lines) | +7.5 | +24.5 |

**Route per book, not per section.** Two candidate section-level features were
tested and neither flips the sign inside a book:

- local tag density: uniformly positive in grimgar03, uniformly negative in
  mushoku16, at every band
- local first-person density: the books behave *oppositely* in third-person
  windows (+6.7 vs −19.4)

The one section-level rule supported is negative: turn tag-priority off in
first-person passages, where it buys nothing in either book.

### The open hypothesis

mushoku16's −19.4 cell (third-person windows in a heavily first-person book)
is most likely the **letter and diary passages** — written text carrying names
but no speech tags, exactly where a trust-the-adjacent-tag rule should
misfire. If true, the routing feature is **passage type** (prose / epistolary /
interior monologue), not tag density or narrative person.

Testing it needs the epistolary sections marked; nothing currently identifies
them. That is the cheapest remaining step and the only one that could still
make per-section routing work.

## Shippable today

- **tag-priority on tag-rich books**: +6.5 on grimgar03 (p=0.001), and it cut
  unattributed rows 33 → 13. Off for mushoku-like books.
- **batch size is not universal**: grimgar03 peaks at 50, mushoku16 at 25.
  Production's fixed 25 leaves ~4 points on grimgar-like books.
- **the disagreement cascade**: run the cheap model at w1 and w4, send the
  ~40% where they disagree to a 70B. 77.8% vs 55.8% on grimgar03
  (p=1.4e-23), 64.0% vs 47.5% on mushoku16. Costs 70% of batches, not 40% of
  rows — the window around each routed line goes too.

## Retracted today

  it. A crutch for weak models, not a lever. Do not ship.
- **joint scene decoding** — loses to per-line on both models. Order inside a
  joint prompt is worth +15.4 on the 70B, but batching costs more than
  ordering returns.
- **voting, adaptive width, committed history** — all null or below cost.
