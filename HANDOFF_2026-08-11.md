## 0. What all of this is FOR — read this first

Everything below serves one document: **`GOALS.md`**, in the repo root.

It defines what "good" means for this app **as numbers a script can check**,
so that quality stops being an opinion. Its own framing:

> Every current value is a measurement with a source you can re-run. Every
> target is a commitment. Where there is no baseline yet, the goal is *to take
> the measurement*, and it says so — an unmeasured target is a wish, and this
> document does not contain wishes.

**33 goals in six areas** — attribution (who says which line), voice fidelity,
reliability, speed/cost, text handling, and measurement integrity. Each carries
a plain-language explanation of why a listener would care, then the metric, the
probe script that counts it, the current value with its evidence, and the
target.

Three statuses, and the third is the important one:

- **MET** — measured at or beyond target. Keep a test so it stays there.
- **OPEN** — measured, below target. The gap is the work.
- **NO BASELINE** — not measured. The first task is the measurement, not the fix.

**Current standing: 23 MET, 11 OPEN** (read off `GOALS.md` on 2026-08-11).

### The three that matter most right now

Straight from the document's own Priority section:

1. **Generalisation (1.3)** — the app scores **71.0%** on 25 PDNC novels it has
   never seen against **83.6%** on the three it quotes: a −12.6 point gap
   against a target of 5. Those three books rank #2, #8 and #9 of 28. *This is
   the largest known overstatement in the document.*
2. **Duration fidelity (2.4)** — the Japanese clone arm runs at 0.758 with 94%
   of clips outside the band, confirmed at n=100.
3. **Train/val contamination (2.7)** — **60 of 75 shipped adapters trained on
   their own val split.** The trainer is fixed; the library is not. Every
   held-out score from a contaminated adapter is an upper bound.

### Two habits this document enforces, which are load-bearing

- **Re-measuring a goal before working on it has twice been worth more than
  working on it.** Selection (1.2) was priority #1 until 2026-08-08 and is now
  MET — the 29.9% it was built on came from a model that does not ship.
- **Rules for changing the file:** a current value moves only with an artifact
  and a date; a target moves only with a stated reason; an OPEN goal is never
  deleted for being difficult — convert it or record why it was abandoned.

So when this handoff says a session "fixed" something, the question that
matters is *which goal moved, and what artifact proves it*. Work that does not
touch a goal is either infrastructure for one that will, or should be justified
as such.

## 3. The starvation problem — READ BEFORE TOUCHING ANYTHING

`decontaminate_library.sh` (5h) and `moss_vs_lora.sh` (2h50m) have produced
**nothing**. Between them they are goals **2.7** (60 of 75 adapters trained on
their own val split — priority #3) and an open question about whether the whole
LoRA pipeline can be replaced by zero-shot cloning. Neither has advanced.

Both sit in this loop:

```bash
while pgrep -f "generate_script.py " >/dev/null 2>&1 \
   || pgrep -f "three_pass_generate.py" >/dev/null 2>&1; do
    echo "waiting for the GPU $(date -u +%H:%M:%SZ)"
    sleep 300
done
```

Generation has run continuously since before they started, so they have never
advanced past the wait.

**Do not delete that wait.** It is a real safety net, not a bug —
`moss_vs_lora.sh` loads an 8B model (MOSS-TTSD) and would OOM against a live
generation. Removing it trades a slow run for a crashed one.

The actual defect is *fairness*: `gpu_job.sh` provides a `flock`-based queue,
but only jobs that opt in respect it. The generation chains never call it, so
a polite chain waits forever behind impolite ones. The fix is to route every
chain through `gpu_job.sh` so there is one queue.

**That fix was NOT applied, deliberately.** All four chain scripts are
currently executing, and bash reads a script lazily as it runs — editing a
running `.sh` can corrupt its execution mid-flight. Apply it only once the
chains have exited.

Two options when someone picks this up:

- Wait ~7.5 h for `arc4_volume10wn`, then apply the `gpu_job.sh` routing.
- Drop `arc4_volume10wn` from the queue now so the two starved chains start in
  about 45 minutes. This changes queued work, so it needs a decision.

## 4. Code changes today

### MERGED — #289, duplicate classification

Finished books were being discarded over duplicates the repair already knew how
to fix. Two causes, neither a defect in the book:

1. **`\w` includes underscore.** Project Gutenberg marks italics with it. The
   source reads `explain _myself_`, the model correctly drops the markup and
   writes `myself`, and the two never matched. **23 of the 28 public-domain
   novels use the convention**, so all of them were being measured against a
   source whose emphasised words could not be matched.
2. **Entries are not contiguous source spans.** `"Explain yourself!"` and
   Alice's reply have `said Alice` between them, so the joined block scores
   zero occurrences while each line scores one — read as "the model invented
   this".

Alice after the fix: 919 → 914 entries, unresolved 0, blocking 0, **gate
passes**. Its recall was never the problem (98.1% token, 96.7% trigram against
a 90% floor).

Pinned by tests in `app/test_duplicate_classification.py`: invented repetition
still deletes nothing, and grimgar03's genuinely repeated title is still kept.

### MERGED — #288, source health preflight

`preflight_source()` in `app/repair_source_encoding.py` checks a source for
known damage before the first LLM call and repairs what it can, in memory. The
user's file on disk is never rewritten.

Wired into both generation paths from one definition, with an agreement test —
a capability living on one path only is the defect shape that has now recurred
four times in this repo.

Corpus scan: **19 of 36 books flagged, 19 fully repairable, no healthy book
flagged.**

Proven end to end: Daisy Miller previously died at chunk 2 of 22; with the
preflight restoring 468 contractions it generated **22/22, 910 entries**.

CI failed once and is fixed: the preflight had been placed *before*
`repair_lossy_replacements` on the three-pass path, so it repaired the U+FFFD
characters itself and the existing repairer reported zero fixes. Text was
identical either way, but the run's self-report went to zero, so the ordering
was wrong rather than the tests. Now runs after. 1502 tests pass.

**Repetition threshold is calibrated from measurement, not intuition:**

| | repetitions |
|---|---|
| runs that demonstrably broke generation (index18) | 25 and 42 |
| legitimate typography, max observed | 13 |

Two earlier versions of that detector flagged healthy books — a stutter
(`I-I-I-I-`), a Japanese scene break (`※　※　※`), a spaced ellipsis. Flagging a
working book is worse than not checking.

### Voice fidelity — the largest thread (#260–#272)

The question was why 74 shipped LoRA adapters scored anywhere from 0.027 to
0.737 on speaker similarity. It was not training settings.

- **The reference clip is causal, and was being chosen by position.** A
  wrong-speaker reference costs **0.541** (#269). Switching selection to the
  **medoid** of the speaker's clips (#266) is the single biggest fidelity fix
  of the week.
- **`extract_val` never created its output directory** (#265), so validation
  splits silently went missing.
- **Training was running on train+val** (#261) — the held-out set wasn't held
  out, so every score before this was optimistic.
- **An "invalid anchor" turned out to be clip length**, nothing subtler (#262).
- **Voice drift was measured for the first time** (#264) and then, one day
  later, **retracted**: the 400-line drift result was noise (#271). Worth
  reading both together — the retraction is the useful artifact.
- **13 voices retrained** with an explicit medoid reference (#270); **7 gated
  adapters promoted** after hash verification (#272).

Note: an earlier claim of "13 voices recovered" was wrong — nothing was
installed at that point. Seven were promoted, after verification.

### ASR and non-English (#260, #274)

### Generation robustness — the index18 / grimgar03 arc (#277–#289)

This is the thread that ran into this session. Five sequential blockers, two
of which were introduced by earlier fixes in the same thread:

1. **`model_name` wasn't recorded when generation failed** (#277) — goal 3.1's
   blind spot, so failures couldn't be attributed to a model.
2. **Retrying an identical prompt at temperature 0** (#278) — deterministic, so
   every retry was guaranteed to reproduce the failure.
3. **A source that repeats itself is not a defect** (#280) — grimgar03 opens
   with its title 8 times and was rejected for faithfully reproducing it.
4. **The source gate is now graded** on replacement characters (#281), so a
   repaired book is usable where any count was previously refused.
5. **The same faithful-duplicate rule reached the whole-book gate** (#283) — it

6. **index18 generates; goal 3.1 MET on the shipped model** (#284).
7. **Quote balance is measured per paragraph, not per physical line** (#287).
   The line version scored all 28 PDNC novels 34.5–84.3% "unbalanced" with

8. **Source health preflight** (#288) and **duplicate classification** (#289) —

The recurring shape across 3, 5, 8: **one decision implemented in several

## 7. Things I got wrong today — do not re-derive these

- **The GPU lock does not prevent contention.** I claimed queuing a job behind
  `gpu_job.sh` would stop it competing. It only serialises jobs that opt in;
  three books generated simultaneously against one endpoint anyway.
- **"The model elides quote-free narration"** — proposed after seeing chunk 10
  drop one contiguous region seven times. Measured it: **7 of 10 dropped
  regions had MORE quotes than their chunk baseline**, not fewer. Dead. What
  survives is only that the losses were contiguous and positional.
- **A waiter that greps `Error:`** matches the benign LM Studio startup warning
  that appears near the top of every generation log. It fires instantly and
  looks like a result. Scope the search to text after the marker you care
  about. This has now cost time three times.
- **`source_occurrences == 0` does not mean invented.** It meant "not
  contiguous" or "differs by an underscore". See §4.
